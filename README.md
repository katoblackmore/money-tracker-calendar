# Money Tracker

Личный денежный учёт с карточками платежей и календарём в тёмном стиле.

## Левая панель

Логотип и название Money Tracker находятся в левой колонке над карточкой «Траты»; отдельной верхней панели нет.

Под курсом НБУ расположены кнопка «Новый платёж» на всю ширину и поиск по шаблонам. Вкладки «Типовые» и «Кастомные» разделяют исходные и пользовательские карточки. В «Типовых» есть разделы «Ежемесячные», «Ежегодные» и «Квартира». Новые карточки создаются в «Кастомных»; ранее созданные пользовательские карточки тоже отображаются там. Вкладки оформлены в тёмной палитре сайта с зелёным выделением. При редактировании карточка сохраняет свой тип. Поиск по названию показывает совпадения из всех вкладок; при очистке поиска возвращается выбранный раздел. Уже внесённые оплаты сохраняются.

Двойной клик по свободной области дня календаря открывает форму нового кастомного платежа с датой этой ячейки. После добавления оплата сразу попадает на выбранный день. Кнопка «Добавить кастомный платёж» доступна во вкладке «Кастомные» и при пустом списке, и при наличии карточек.

## Создание платежа

В окне «Новый платёж» доступны название, необязательная ссылка на приобретённый товар, сумма, валюта USD/UAH, периодичность «Единоразово / Ежемесячно / Ежегодно», раздел «Без раздела / Подписки / Квартира» и необязательная дата оплаты через встроенный календарь. Валюта, периодичность и раздел выбираются в крупных списках в стиле сайта. Новая карточка по умолчанию единоразовая и без раздела; все новые карточки попадают в «Кастомные». Дата начала и заметки из формы убраны. Если при создании указана дата, платёж сразу добавляется в календарь и в сумму трат, а календарь переключается на выбранный месяц. Без даты сохраняется только карточка; её можно перетащить на календарь позже. Редактирование карточки не создаёт повторную оплату.

## Темы оформления

Кнопка с шестерёнкой рядом с Money Tracker открывает настройки. Доступны восемь схем — Лайм, Океан, Лаванда, Роза, Янтарь, Мята, Коралл, Графит — и независимый выбор светлого или тёмного режима. Цвета применяются ко всему интерфейсу, включая календарь, формы и списки. Выбор сохраняется в этом браузере отдельно от платежей.

## Категории и траты за месяц

Под ссылкой в форме платежа находится список из 25 категорий. Исходным шаблонам категории подбираются автоматически; существующие кастомные карточки без категории считаются «Другое». Категорию можно изменить при редактировании. Для новых оплат категория сохраняется вместе с фактической суммой и валютой, чтобы изменение шаблона не меняло историю.

Кнопка со списком рядом с настройками открывает все траты выбранного месяца. Доступны фильтры по исходной валюте и категории, сортировка по дате, сумме или категории, разбивка по категориям или валютам. Переключатель USD/UAH задаёт валюту отображения; при сортировке суммы разных валют пересчитываются по текущему курсу НБУ. Навигация по месяцам синхронизирована с календарём.

Справа от календаря — панель оплат выбранного месяца. По умолчанию панель скрыта при открытии страницы. Кнопка «Список оплат» показывает или скрывает панель; крестик закрывает её. На узких экранах панель открывается поверх календаря. Список, итог и отчёт обновляются после добавления, изменения и удаления оплаты.

## Перенос оплаты

Оплату в календаре можно перетащить на другую дату. Перенос изменяет дату записи и дату в карточке, сохраняя фактическую сумму, валюту и категорию оплаты. У ежемесячного шаблона меняется день оплаты, у ежегодного и единоразового — дата. Другие внесённые оплаты не перемещаются. При переносе на соседний месяц календарь открывает этот месяц, списки и итоги пересчитываются. Если на выбранной дате уже есть оплата этой карточки, перенос отменяется без потери записей. Обычный клик по оплате по-прежнему открывает её редактирование.

## Возможности

- Верхняя карточка «Траты» показывает общую сумму внесённых оплат за выбранный месяц в USD и UAH.
- Добавление, редактирование и удаление карточек платежей.
- Отдельные разделы: ежемесячные подписки, квартира и ежегодные платежи.
- Оплаты вносятся вручную: при создании платежа с датой или перетаскиванием на календарь. Повторяющиеся оплаты сами не добавляются.
- Перетаскивание карточки на дату календаря добавляет оплату с суммой карточки. Дубликаты одной карточки на одной дате не создаются. На сенсорном экране можно выбрать карточку касанием, затем коснуться даты; с клавиатуры — выбрать карточку Enter и перейти к нужной дате.
- Редактирование и удаление внесённой оплаты через запись в календаре.
- Суммы в USD и UAH расположены рядом в карточках всех типов.
- Официальный курс НБУ на текущую дату в часовом поясе Europe/Kyiv; обновление при открытии, каждый час и кнопкой ↻. При недоступности НБУ используется последний сохранённый курс с указанием его даты.
- Данные сохраняются в localStorage браузера. Импорт и экспорт отсутствуют.

При первом открытии добавлены 12 карточек из первоначального списка. Изменения карточек и оплаты хранятся в браузере, а не в файлах репозитория. После удаления данных браузера они будут потеряны. Между устройствами данные не синхронизируются. Новый домен GitHub Pages будет иметь собственное хранилище; записи с текущего сайта туда автоматически не переносятся.

## Сохранение изменений в браузере

Сохранение происходит автоматически после добавления, редактирования, удаления и перетаскивания оплаты. В localStorage сохраняются карточки и их названия, суммы, валюты, ссылки, категории, периодичность и выбранные даты; фактические оплаты со своими суммами, валютами и категориями; перенесённые даты; последний успешно полученный курс НБУ. Тема и цветовая схема сохраняются отдельно от финансовых данных.

Перезагрузка страницы и закрытие/повторное открытие браузера не сбрасывают эти данные при обычном режиме работы. Правая панель при открытии страницы остаётся скрытой по умолчанию. Незавершённые формы и временные фильтры не сохраняются.

Хранилище принадлежит конкретному адресу сайта, профилю браузера и устройству. Перенос исходников на GitHub Pages не переносит записи с localhost. Очистка данных сайта или завершение приватной сессии может удалить локальные данные. Серверной базы данных и межустройственной синхронизации нет.

## Публикация на GitHub Pages

1. Создайте репозиторий на GitHub.
2. Распакуйте архив. Загрузите **содержимое** папки `money-tracker` в корень репозитория: `index.html`, `app.js`, `style.css` и остальные файлы. Не загружайте ZIP вместо исходников.
3. Откройте **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**.
5. Выберите ветку **main** и папку **/ (root)**, затем **Save**.
6. Дождитесь публикации. Ссылка появится в разделе Pages.

Приложение не требует сборки, установки зависимостей или ключей API.

Доступность GitHub Pages для приватного репозитория зависит от плана GitHub. Приватность репозитория сама по себе не означает приватность опубликованного сайта: в этой версии нет входа в аккаунт или серверной проверки доступа. Начальные названия и суммы карточек находятся в `app.js` и доступны посетителям опубликованного сайта. Фактически внесённые оплаты остаются в браузере пользователя.

Официальная инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

Календарь занимает доступную ширину и высоту окна; в настольной версии левая колонка прокручивается отдельно. На узком экране блоки располагаются друг под другом.

## Локальный запуск

Из папки проекта запустите:

```sh
python3 -m http.server 8000
```

Откройте http://localhost:8000. Интернет нужен для обновления курса НБУ.

## Проверки

При установленном Node.js 20 или новее:

```sh
npm test
```

Установка пакетов не требуется. Проверяются пустой календарь, ручное внесение ежемесячных и ежегодных оплат, выбранные даты и суммы, удаление оплат, отсутствие автоматических повторений и загрузка сохранённых данных.

## Файлы

- `index.html` — интерфейс.
- `style.css` — оформление и адаптация к размеру экрана.
- `app.js` — карточки, оплаты, календарь, траты, курс и хранение данных.
- `checks/verify.cjs` — проверки поведения.
- `.nojekyll` — публикация статических файлов без обработки Jekyll.

В архиве нет истории Git, служебных данных Sites, токенов и фактических записей из браузера.
